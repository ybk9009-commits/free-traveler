# UI/UX Plan — Free Traveler

- **Document ID:** UIUX-TRAVEL-001
- **기반 문서:** `01_PRD.md`, `02_SRS_BASELINE.md`, `PROJECT_SCOPE.md`, `03_UI_COVERAGE_ANALYSIS.md`
- **참고 자료:** `design-reference/vendor/airbnb/DESIGN.md`(구조 참고용. Rausch 색상, Airbnb Cereal 서체, "Guest favorite"/"NEW" 배지, 손그림 아이콘 등 상표적 요소는 사용하지 않는다)
- **범위:** SCR-001~SCR-005 5개 디자인 Screen의 공통 디자인 시스템, Section 구성, 상태 정의

Airbnb 레퍼런스에서는 "흰 캔버스 + 단일 액센트 컬러 + 사진 중심 카드 그리드 + 절제된 그림자"라는 **구조적 접근**만 차용한다. Free Traveler는 코랄 액센트 1색, 짙은 회색 텍스트, Inter 기반 타이포그래피로 별도 브랜드 아이덴티티를 구성한다.

### 1.5 접근성 원칙

- 키보드 포커스는 항상 `color.focus-ring`(#1D4ED8) 2px 아웃라인 + 2px 오프셋으로 표시하며 `outline: none`으로 제거하지 않는다.
- 모든 클릭 가능 요소(버튼, 탭, 칩, 카드 CTA, 아이콘 버튼)는 최소 44×44px 터치 영역을 확보한다. 시각적 크기가 작은 아이콘 버튼(예: 즐겨찾기 하트)은 패딩으로 44px 히트 영역을 채운다.
- 색상 대비는 텍스트 기준 WCAG 2.2 AA(4.5:1) 이상을 목표로 한다.
- 경보·오류·상태 배지는 색상 + 텍스트 라벨 + (필요 시) 아이콘의 3중 표기를 기본으로 한다.

## 2. 공통 컴포넌트

### 2.1 Header (5개 Screen 공통)

- 구성: 좌측 `Free Traveler` 워드마크(텍스트 로고, 코랄 포인트 없이 `color.ink`) · 중앙 내비게이션(여행지, 여행 준비, 동행 찾기, 대표 소개) · 우측 계정 영역(로그인 전: "로그인" 텍스트 버튼 / 로그인 후: 아바타+닉네임 메뉴).
- 데스크톱 높이 72px, 흰 배경, 하단 1px `color.hairline`. 모바일(< 744px)은 로고+햄버거 메뉴로 축약, 내비게이션은 풀스크린 시트로 펼침.
- 내비게이션 5개 항목은 각각 SCR-001~SCR-005로 직접 연결된다(여행지→`/`, 여행 준비→`/travel-tools`, 동행 찾기→`/mates`, 대표 소개→`/about`, 계정→`/account`).
- 활성 라우트는 `color.primary` 텍스트 + 하단 2px 코랄 밑줄로 표시.

### 2.2 Footer (5개 Screen 공통)

- 3열 구성(Desktop): 서비스 소개(브랜드 한 줄 + 여행 준비/동행 찾기/대표 소개 링크) · 정책(이용약관, 개인정보 처리방침, 동행 안전수칙, 콘텐츠 면책 안내) · 안전 정보 출처(외교부 해외안전여행 링크, "정보는 참고용이며 출국 전 공식 출처 재확인이 필요합니다" 고지).
- 하단 legal band: `© Free Traveler` 저작년도, 문의 링크. 모바일은 1열로 스택.
- 배경은 `color.surface-soft`로 본문 캔버스와 미세하게 구분한다.

### 2.3 Button

| 컴포넌트 | 배경 | 텍스트 | radius | 높이 | 용도 |
|---|---|---|---|---|---|
| `button.primary` | `color.primary` | 흰색 | `radius.sm` | 48px | 핵심 CTA(외부 이동, 신청, 로그인, 제출) |
| `button.primary:disabled` | `color.primary-disabled` | 흰색 | `radius.sm` | 48px | 필수값 미입력 시 |
| `button.secondary` | 흰색 + 1px `color.ink` 테두리 | `color.ink` | `radius.sm` | 48px | 보조 액션(취소, 필터 초기화) |
| `button.tertiary-text` | 투명 | `color.ink` | — | 44px | "더 보기", Drawer 닫기 |
| `chip` | 흰색(기본)/`color.primary-soft`(선택) | `color.body`/`color.primary` | `radius.full` | 40px | 테마·필터 칩 |

### 2.4 Card

- `card.destination`: 4:3 이미지(상단, `radius.lg` 클리핑) + 하단 메타(제목 `type.title-md`, 국가/지역 `type.body-sm` muted, 추천 시기 캡션 칩) + 우상단 즐겨찾기 아이콘 버튼.
- `card.safety`: 국기/국가명 + 경보단계 배지(색상+텍스트) + 최종 확인일 캡션 + (7일 초과 시) stale 경고 배지.
- `card.mate`: 제목 `type.title-md`, 국가·기간·모집인원 메타 행, 여행 스타일 칩 1~2개, 모집상태 배지(모집중/마감).
- `card.timeline-item`: 연도 캡션 + 장소 제목 + 2줄 요약.
- 카드 hover 시 `elevation.card-hover` 적용, 카드 자체 정지 상태는 그림자 없이 1px `color.hairline` 테두리만 사용한다.

### 2.5 Tabs

- 밑줄형 탭(`tab.underline`): SCR-003(항공/숙소/동행), SCR-005(프로필/내 활동/관리). 활성 탭은 `color.ink` 텍스트 + 2px 코랄 밑줄, 비활성은 `color.muted`.
- 탭 전환 시 다른 탭의 입력 상태는 유지하되(같은 세션 동안) 검증·제출 상태는 탭별로 독립적으로 관리한다.

### 2.6 Drawer / Modal

- Desktop: 우측에서 슬라이드인하는 Drawer(폭 480~560px, 전체 높이, `elevation.drawer-modal`). 여행지 상세, 안전정보 상세, 동행 상세(Mobile 한정)에 사용.
- Mobile: 하단에서 슬라이드업하는 풀스크린 시트로 전환.
- 상단 고정 헤더에 제목 + 닫기 버튼(44px), 본문은 스크롤 가능, 하단 고정 CTA 영역을 둘 수 있다.

### 2.7 Badge / 상태 표기

| 배지 | 색상 | 텍스트 예시 |
|---|---|---|
| 모집중 | `color.primary-soft` 배경 + `color.primary` 텍스트 | "모집중" |
| 마감 | `color.surface-strong` 배경 + `color.muted` 텍스트 | "마감" |
| stale 경고 | `color.warning-soft` 배경 + `color.warning` 텍스트 | "최신 정보 재확인 필요" |
| 경보 1~4단계 | `color.safety-*` 텍스트 + 옅은 배경 | "여행유의" / "여행자제" / "철수권고" / "여행금지" |
| 오류 | `color.danger-soft` 배경 + `color.danger` 텍스트 | "입력값을 확인해 주세요" |

### 2.8 Form Input

- 흰 배경, 1px `color.hairline` 테두리, `radius.sm`, 높이 52px, 라벨은 필드 위 `type.caption`.
- 포커스 시 테두리 2px `color.focus-ring`. 오류 시 테두리 `color.danger` + 필드 하단에 오류 문구(아이콘+텍스트), `aria-describedby`로 프로그램적 연결.

### 2.9 Empty State 블록

모든 Empty State는 다음 3요소를 반드시 포함한다: ① 상황 설명 한 문장(왜 비어 있는지) ② 이용 방법 또는 조건 안내 ③ 다음 행동 CTA 버튼. 아이콘/일러스트는 장식용으로만 두고 텍스트 없이 아이콘만 두지 않는다.

### 2.10 Toast

- 화면 우하단(Desktop) / 화면 상단(Mobile) 고정, `radius.md`, 3~5초 자동 소멸 + 수동 닫기 버튼. 성공은 `color.success` 아이콘, 오류는 `color.danger` 아이콘을 좌측에 둔다.

## 3. 콘텐츠 밀도 및 Section 배치 원칙

- 모든 화면은 Header–Footer 사이에 목적이 분명한 Section을 순서대로 배치하며, SCR-001·SCR-002는 7개, SCR-003·SCR-004는 6개, SCR-005는 역할별 가변 탭 구성을 기본으로 한다.
- Desktop 콘텐츠는 1200~1280px 폭에 중앙 정렬하고 Section 상하 여백은 64~96px, Mobile은 40~64px로 좁히며 Card는 1열로 쌓는다.
- Hero는 데스크톱 기준 화면 높이의 60~70%(약 520~600px)만 차지해 1440px 화면에서도 다음 Section의 상단 일부가 보이도록 한다.
- Section 레이아웃 패턴은 Hero, Card Grid, 좌우 분할(이미지+텍스트), Chip 목록, 3단계 안내, CTA Banner를 화면마다 교차 배치해 동일한 Card 그리드만 반복되지 않게 한다.
- Lorem ipsum, "준비 중", "정보 확인 필요"와 같은 자리표시 문구, 의미 없는 빈 카드, 과도한 빈 여백을 두지 않는다. 콘텐츠 소스가 비어 있는 상태(DB/정적 데이터 없음)에도 2.9의 Empty State 블록으로 대체한다.
- 모든 이미지는 실제 장소를 설명하는 대체텍스트를 갖는다(예: "제주 성산일출봉 전경", 일반적인 "이미지"·"사진" 대신 장소·상황을 명시).

| 외부 URL 설정 | `FLIGHT_OUTBOUND_URL`, `HOTEL_OUTBOUND_URL`, 안전정보 공식 출처 URL 입력 Form(HTTPS만 허용) | REQ-FUNC-077 |

관리 탭은 통계 차트나 대시보드 형태를 사용하지 않고 목록 + 상태 변경 액션으로만 구성한다.

## 6. Requirement 반영 확인

- `03_UI_COVERAGE_ANALYSIS.md`에서 UI_DIRECT·UI_STATE로 분류되고 SCR-001~SCR-005에 배치된 요구사항은 모두 위 4절의 Section 또는 Drawer/Modal/탭 구성에 반영했다.
- NON_UI·OPERATIONS로 분류된 요구사항(서버 저장 정책, RLS, 감사 로그, CI 게이트 등)은 화면 요소를 만들지 않으며, 이 문서에서도 별도 화면으로 설계하지 않았다.
- EXCLUDED로 분류된 기능(전체 콘텐츠 CMS, 미디어 업로드 워크플로, 감사 로그, stale 대시보드 등)은 SCR-005 관리 탭에도 포함하지 않았다.
- 디자인 Screen은 SCR-001~SCR-005 5개로 고정했으며, API Route·인증 콜백·404/500 오류 경계는 기술 Route로 유지하고 별도 Screen으로 세지 않았다.
